## What's New (User Facing)
* No user facing release went out in Sprint 1 because this sprint was focused on planning and documentation
* We defined the first set of chatbot behaviors users will expect, including chat history, station clarification and clearer error handling
* We documented the main question types the chatbot should support, including live, historical, forecast and aggregate weather queries

## Work Summary (Developer Facing)
Sprint 1 was about catching up and building a solid starting point before we moved into implementation. We met with the client four times during the sprint to clarify what the new chatbot needed to do, what went wrong with the previous version and which technologies made the most sense for this redesign. From those meetings, we completed the project introduction and a detailed set of functional and non functional requirements, while also drafting user stories, use cases and UML diagrams for the core chatbot flow. We also spent time learning the tools and ideas that will matter next, especially RAG, React, Python and cloud deployment planning. By the end of the sprint, we had a much clearer project scope, a shared understanding of the chatbot workflow and enough structure to move into architecture and prototype work in Sprint 2.

## Unfinished Work
We did not start application implementation in Sprint 1, and we also did not lock the final system architecture yet. That was intentional because the team wanted to finish gathering requirements, review the old solution and get aligned with the client before committing to a design. In Sprint 2, we plan to turn this documentation into architecture proposals, prototype work and a more detailed implementation backlog.

## Retrospective Summary
Here's what went well:
* We captured the main functional and non functional requirements early, and focused our project scope
* We built a consistent meeting rhythm with the client and got clearer answers each week
* We aligned on an initial stack built around React, Python, MySQL, AWS and RAG, Lang Chain

Here's what we'd like to improve:
* Build stronger background knowledge in AI and large language model system design
* Decide on a model that is optimal for computing costs that still performs well
* Spend more time getting familiar with the client data and schema early
* Develop a clearer plan for RAG testing and validation

Here are changes we plan to implement in the next sprint:
* Finalize the system architecture and compare a few RAG pipeline options with the client
* Start prototype work for the chatbot backend and the first UI mockups
* Turn the finished requirements into a more detailed implementation backlog
